# Pilot 05 (P05): first OKN contrast-response feasibility study

**Question:** do iPhone-measured OKN slow-phase velocity and direction
consistency change systematically with the contrast of a moving grating?

**Status:** exploratory feasibility only.
- No thresholds, psychometric fits or contrast-sensitivity claims.
- **Every contrast below is nominal**, set in software under an assumed display
  curve and not photometrically measured.
- Nothing has been recorded yet.

## Design

**Condition:** regular OKN only. The participant watches the moving stripes
naturally.
- There is no fixation dot, and fixation conditions are not mixed in.
- The **instruction is identical for every trial and every contrast,
  including 0 %**: "Keep your head still and watch the screen." It names no
  direction, so a 0 % trial gives no cue.

**Contrast levels:** six nominal Michelson contrasts, 0, 5, 10, 20, 40 and 80 %.
- **0 % is a spatially uniform field at the same mean luminance.** The grating
  still moves, invisibly, and its direction and speed are recorded.
- **It is not the Pilot 03/04 still-stripe control.** The instruction, the
  absence of a dot and the motion state all differ. Analysis scores 0 %
  trials against their intended direction like any other trial.

**Directions:** LEFT and RIGHT at every level, at the same speed (126 pt/s,
about 4.4 deg/s at 27 cm).

**Plan:** two participants (P01, P02) × 6 contrasts × 2 directions × 2
repetitions = **24 recordings per participant, 48 in total**. Each recording
is 10 s.

**Order:** two blocks of 12 per participant. Each block contains every contrast
× direction cell once. The orders are seeded random draws with two constraints:
- the same contrast is never twice in a row;
- each contrast's mean position in the session is within 2.5 positions of
  every other's, so low contrasts aren't systematically early or late.

The orders are fixed below and were drawn before any recording.

## Contrast implementation (`NystagmuSense/Models/GratingContrast.swift`)

**Definition:** Michelson contrast C = (Lmax − Lmin) / (Lmax + Lmin) on
**relative luminance** L, where 0 is black and 1 is display white.

**Holding the mean constant:** dark bars cover d = 1/2.4 = 41.7 % of each
period. So the background and bar luminances are chosen to keep the
area-weighted mean luminance at 0.5 for every contrast:

```
x = 2C / (1 + (1 − 2d)C);   Lbackground = 0.5 (1 + d x);   Lbar = 0.5 (1 − (1 − d) x)
```

**Rendering:** luminance is converted to the code value drawn with
`Color(white:)` by the inverse sRGB transfer function. RGB code values are not
luminance, so a naive "gray × contrast" would be wrong. The Python mirror
`analysis/pilot_05/contrast_model.py` must produce identical code values; a
shared test fixture checks both sides.

| Level | L background | L bar | Code background | Code bar | 8-bit codes | Contrast after 8-bit rounding |
|---|---|---|---|---|---|---|
| 0 % | 0.500 | 0.500 | 0.7354 | 0.7354 | 188 / 188 | 0.00 % |
| 5 % | 0.521 | 0.471 | 0.7488 | 0.7160 | 191 / 183 | **4.77 %** |
| 10 % | 0.541 | 0.443 | 0.7617 | 0.6962 | 194 / 178 | 9.57 % |
| 20 % | 0.581 | 0.387 | 0.7862 | 0.6554 | 200 / 167 | 19.83 % |
| 40 % | 0.656 | 0.281 | 0.8302 | 0.5669 | 212 / 145 | 39.85 % |
| 80 % | 0.794 | 0.088 | 0.9034 | 0.3287 | 230 / 84 | 79.85 % |

**Unchanged across levels:** speed, stripe width and pitch, direction,
screen layout and timing. Only the two grey levels change.

**Before and during recording:**
- Before onset the static first frame is shown at the trial's contrast, so
  onset isn't a brightness step.
- During recording the status card is hidden for Pilot 05, so nothing but the
  grating is on screen. It returns when the trial ends.
- There is no Cancel during the 10 s. Leaving the app cancels the trial.

### What remains uncalibrated

- **The display curve.** iPhone panels are colour-managed (Display P3).
  Whether sRGB greys are reproduced with the exact sRGB curve, and what
  absolute luminance results, is unknown without a photometer. Brightness,
  True Tone, Night Shift and Auto-Brightness all change it.
- **Quantisation.** At 8 bits the 5 % level is only 8 code steps (4.77 %
  under the assumed curve). If the pipeline renders at 10 bits, the levels are
  within 0.06 points. The 5 % level is the least reliable.
- **Edge antialiasing.** Bars move by fractional pixels, so edge pixels take
  intermediate values. Mean luminance is unaffected; edge contrast is softened
  slightly.
- **Viewing geometry.** The ARKit distance is uncalibrated, so deg/s and
  cycles/deg are estimates.

### Photometer (recommended before any threshold work)

**What's needed:** a luminance meter (cd/m²) and a full-screen solid patch at
each code value. The bars are about 2.9 mm wide, too narrow for most meters.

**A solid-patch display mode isn't implemented.** Measuring through the
stripes needs a spot meter of 2 mm or smaller.

**With the session settings** (max brightness, True Tone, Night Shift and
Auto-Brightness off, same room), measure:
1. every background and bar code above, including the 0 % grey;
2. white (1.0) and black (0.0);
3. a 0 % field at screen centre and the four quadrants, for uniformity;
4. each level again after 10 min, for drift.

From those, compute the actual Michelson contrast and the mean luminance per
level, and record the results next to the analysis.

**Interpreting the feasibility criteria below doesn't need it.** Any
contrast threshold or contrast-sensitivity estimate does.

## File names and metadata (file-name contract 2)

```
P05-{P01|P02|P03}_T{trial}_OKN_{LEFT|RIGHT}_C{nominal contrast %, 3 digits}_{UTC yyyyMMdd_HHmmss}
e.g. P05-P01_T120_OKN_LEFT_C020_20261113_150100       (C000 = 0 %, C005 = 5 %, ... C080 = 80 %)
```

**Contract 2 only adds the optional `_C###` field.** Every earlier name is
unchanged and still valid, and the CSV and JSON share the name.

**Sidecar schema 7** adds `stimulus.michelsonContrast` (0–1, nominal) and
`stimulus.meanRelativeLuminance` (0.5). The derived code values are in
`stimulus.fixedBackgroundGray` and `stimulus.stripeGray`. The sidecar also
records `stimulus.direction`, `speedPointsPerSecond`, `participantID` and
`experimentID "P05"`.

**The receiver refuses** a pair whose contrast field and metadata disagree.
Identical retries return "already received"; a different recording under an
existing name is refused, never overwritten.

## Feasibility criteria (fixed before collection)

These are hypotheses, not guaranteed outcomes or clinical thresholds.
`analysis/pilot_05/analyze_contrast.py` reports each one; none is tuned after
seeing data.

1. **High-contrast response:** at 40 % and 80 %, each participant's median
   aligned slow-phase velocity is > 0 and the median direction consistency is
   > 0.5.
2. **Weak 0 % response:** each participant's median aligned velocity at 0 % is
   below 25 % of their median at 80 %.
3. **Rising with contrast:** within each participant, Spearman ρ between
   contrast and aligned velocity is > 0. A perfectly monotonic curve isn't
   required.
4. **Direction reversal:** at ≥ 20 %, the slow-phase drift has the expected
   sign for its direction in ≥ 90 % of trials.
5. **Repeatability** (reported): the median spread between the two repeats of
   a cell, compared with the range of medians across contrast.
6. **Tracking** (reported): within each level, ρ between the tracked fraction
   and the response. Values near 0 suggest tracking loss doesn't explain the
   curve.

**Screen brightness** is held constant by design (constant mean luminance);
its photometric check is listed above.

**Not done:** thresholds, fits or adaptive testing.

## Limitations

- **Two people, one session.** P01 and P02 already took part in Pilots 03 and 04.
- **Nominal contrast and uncalibrated units**, as above.
- **Detection isn't sensitivity.** A response that changes with contrast is a
  prerequisite for contrast sensitivity, not a measurement of it.

### Review corrections before collection

Technical checks reject non-finite display codes, changes to the protocol stripe
width or pitch, and contrast values that merely round to the name's percentage.
The receiver also rejects missing, non-finite and out-of-range contrast metadata.
Unavailable slow-phase responses remain in the direction-reversal denominator
and count as failures; they cannot inflate the 90 % criterion. Plots can be
written even when all responses are unavailable. These checks do not change
the frozen detector or response scores.
